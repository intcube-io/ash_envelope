# Step 6: Security Requirements

Each requirement traces back to at least one security goal from step 2 and at least one rated threat from step 4. Common Criteria class hints reference ISO/IEC 15408-2.

## Security Requirements (SRs)

| ID | Requirement | Goal(s) | Threat(s) | CC class |
|---|---|---|---|---|
| **SR2** | The library shall document, for each KeyManager it ships (`AshEnvelope.BlobIO.KeyManagers.Asymmetric`, `AshEnvelope.BlobIO.KeyManagers.KeyGrants`), the threat classes the manager defends against and those it does not. This documentation shall live alongside the user-facing tutorials and be cross-referenced from the KeyManager moduledocs. | SG6, SG9 | T2 | FPT |
| **SR3** | The library shall encrypt field-data plaintext (via `AshEnvelope.encrypt/3` and `decrypt/3`) and shall perform the inner AEAD step of the ECIES wrap and the symmetric seal step (`AshEnvelope.SealKey`) using AES-256-GCM with a 12-byte random IV per call. Each DEK shall be wrapped using X25519 ECIES with a fresh ephemeral key pair per call. `encrypt/3` and `decrypt/3` shall accept optional `:context` AAD (used to bind a ciphertext to a row); empty AAD shall round-trip ciphertexts written without context. No alternative algorithm shall be reachable through the public API without an explicit configuration change. Byte-level encryption of **blob** plaintext is owned by `AshStorage.Layer.Encryption` (separate surface); single-key field encryption with a vault-managed key belongs to [`ash_cloak`](https://hexdocs.pm/ash_cloak). | SG1, SG2, SG6 | T2, T14 | FCS_COP |
| **SR4** | HKDF-SHA256 used for ECIES key derivation shall produce outputs of at most 32 bytes; the library shall reject lengths above this so that callers cannot silently truncate the derived key. | SG6 | T2, T14 | FCS_CKM |
| **SR5** | Library-provided generators (`mix ash_envelope.gen.*`) shall scaffold any principal-private-key attribute as encrypted-at-rest at the integrator's data layer (Cloak-style column encryption or equivalent). The generator shall not produce a plaintext private-key column by default. | SG3, SG7 | T3 | FMT, FCS_CKM |
| **SR6** | The library shall document, in the getting-started tutorial and in the `AshEnvelope.KeyGrants` moduledoc, that integrators must store principal private keys at a protection level at least equal to the protection level of the encrypted data (EA2). | SG3, SG9 | T3 | FPT, FMT |
| **SR7** | The library shall document that envelope integrity is bounded by the integrity of the integrator's database and object storage. Specifically: an adversary with write access to those stores can substitute the entire envelope (ciphertext plus all wrap rows) using only the recipients' public keys, and the library does not cryptographically prevent this. Integrators with such threats are directed to layer signed audit logs, append-only storage, or WORM controls on top. | SG2, SG9 | T4 | FPT, FDP_SDI |
| **SR8** | Reconciliation correctness invariants shall be covered by automated tests: (a) `Runner.plan` produces a grant entry only when `Ash.can?({subject, :read}, principal)` is true and no grant currently exists for `(principal, subject_id)`; (b) `Runner.plan` produces a revocation entry only when a grant currently exists and `Ash.can?({subject, :read}, principal)` is false; (c) `apply_plan!` never inserts a grant row whose wrapped DEK can be opened by any private key other than the target principal's. | SG4, SG5 | T6 | FDP_ACC, FDP_IFC |
| **SR9** | When reconciliation runs in `:async` mode, the Oban job args shall contain only identifiers (subject ids, principal id, actor id). A CI test shall execute a representative async-dispatch path and assert via inspection of `Oban.Job.args` that no value present matches any DEK or private-key byte sequence in scope. | SG3 | T7 | FDP_RIP |
| **SR10** | The library shall not write raw DEKs, principal private keys, or decrypted plaintext to any logger or telemetry handler at any level. A CI test shall exercise the public API of `AshEnvelope`, `AshEnvelope.KeyGrants`, `AshEnvelope.GrantRequests`, and the BlobIO key managers (`AshEnvelope.BlobIO.KeyManagers.Asymmetric`, `AshEnvelope.BlobIO.KeyManagers.KeyGrants`) with fixed plaintext and key material, capture all log output, and assert that no byte subsequence of the captured output matches any of those inputs. | SG3 | T8 | FDP_RIP, FAU |
| **SR13** | Public APIs that mutate or read key-grant material (`AshEnvelope.KeyGrants.create_for_actor/5`, `share/5`, `resolve_for_actor/4`, `revoke/3`; `AshEnvelope.GrantRequests.create/6`, `fulfill/6`, `fulfill_outstanding/5`) shall default to `authorize?: true`. Bypassing authorization shall require an explicit opt-in supplied by the caller. | SG4, SG7 | T10 | FDP_ACC, FDP_ACF |
| **SR14** | The library shall provide a test helper (e.g. `AshEnvelope.TestHelpers.assert_policies_defined!/2`) that, given an integrator's grants resource module, raises a descriptive error if (a) `Ash.Policy.Authorizer` is not configured; (b) no Ash policies are defined; or (c) for each action type in a configurable required set (defaulting to `[:read, :create, :destroy]` ∩ actions the resource defines), no policy's `condition` could possibly apply. The helper shall be documented as a recommended addition to the integrator's test suite. | SG4 | T10 | FDP_ACC, FMT |
| **SR15** | `AshEnvelope.GrantRequests.create/6` shall be idempotent against the identity `(subject_id, target_principal_id, fulfilled_at is nil)`: a concurrent or repeated invocation for the same triple shall return `:ok` without producing a duplicate row. The race-recovery branch (catching a unique-constraint violation and re-checking) shall be covered by a concurrency test. | SG8 | T12 | FRU_RSA |
| **SR16** | The library shall document, in the `AshEnvelope.KeyGrants` and `AshEnvelope.GrantRequests` moduledocs, that the grants and grant-requests tables expose grant-relationship metadata (i.e. which principal has access to which subject) to any reader of those tables, and that the library does not provide cryptographic concealment of this relationship. Integrators with stronger privacy requirements are referred to encrypted-index designs (out of v1 scope). | SG6, SG9 | T13 | FPR_UNL |
| **SR17** | The library's cryptographic-algorithm choices (AES-256-GCM, X25519, HKDF-SHA256) shall be annotated in source with the BSI TR-02102 horizon they are accepted under. The project shall document a review cadence under which BSI TR-02102 publications (and equivalent guidance) are checked at least annually, with results recorded in the project changelog. | SG9 | T14 | FCS_CKM, FMT |
| **SR19** | When `:backup_public_key` is configured, the BlobIO KeyManagers (`AshEnvelope.BlobIO.KeyManagers.Asymmetric`, `AshEnvelope.BlobIO.KeyManagers.KeyGrants`) shall embed an X25519 ECIES wrap of the DEK under `wrapped_dek["backup"]` in encryption-layer metadata, tagged with a `key_id` fingerprint of the wrapping public key. Recovery shall be exposed only via the dedicated `AshEnvelope.recover_dek/2` / `AshEnvelope.recover_plaintext/3` entry points which require the caller to supply the backup private key out of band; no configured KeyManager unwraps from the backup field. | SG3, SG6 | T15 | FCS_CKM, FDP_RIP |
| **SR20** | `mix ash_envelope.rotate_backup_key` shall exit with non-zero status when, after the rotation pass, any blob in the named resources still carries a `wrapped_dek["backup"]["key_id"]` that does not match the fingerprint of the currently-configured `:backup_public_key`. The behaviour shall be locked by an automated test that prepares stale blobs and asserts the exit code. The CLI shall additionally provide a `--check-only` mode that reports the same count without writing. | SG8 | T16 | FPT_FLS, FRU |
| **SR21** | `AshEnvelope.SealKey` shall use AES-256-GCM with a per-call 12-byte random IV and shall bind ciphertext to a caller-supplied AAD (the subject id when invoked by `KeyGrants.create_ephemeral/5`). The library shall reject row-relocation attacks at the unseal step. | SG2, SG6 | T18 | FCS_COP, FDP_SDI |
| **SR22** | The `AshEnvelope.SealKey` ciphertext format shall include a leading version byte to permit future multi-key resolution without rewriting at-rest values. Decoders shall reject unknown versions explicitly. | SG6, SG9 | T17, T18 (forward-compat) | FCS_CKM |
| **SR23** | `AshEnvelope.KeyGrants.renew_ephemeral_with_actor/5` shall be the primary admin API for re-running analyzers after the TTL window. It shall validate the actor's authority via `KeyGrants.resolve_for_actor/4` **before** destroying any existing ephemeral row. `renew_ephemeral/5` shall be documented as a primitive reserved for backup-escrow flows. | SG4, SG7, SG8 | T19 | FMT, FDP_ACC |
| **SR24** | Time-bounded user grants and ephemeral worker grants shall be opt-in via the `:expires_at_attribute` field on `KeyGrants.Config`. When it is `nil`, `KeyGrants` and the `KeyGrants` BlobIO manager shall behave byte-identically to v0.3.0; existing deployments incur no change. | SG6 | T17, T18 | FPT, FMT |
| **SR25** | The library shall not provide an API to refresh `expires_at` on a live grant row. `renew_ephemeral/5` and `renew_ephemeral_with_actor/5` destroy-and-recreate; they do not extend. The TTL is set at create time and respected unconditionally. | SG6, SG7 | T18 (caps time-bound blast radius) | FPT, FMT |
| **SR26** | The library shall document the rotation runbook for the env seal key as "set new key, wait for the maximum configured TTL, retire the old key" and shall **not** provide an in-place rotation tool that re-seals existing rows. Drain-only rotation is the supported model. | SG9 | T17, T18 | Documentation |
| **SR27** | The library shall document, in the `expiring-grants` topic and in the `AshEnvelope.KeyGrants` moduledoc, that **the read policy is the access-control truth and `expires_at` is a grant-lifecycle convenience.** Integrators who need "access ends at time X regardless of policy" must encode the bound in the read policy. `mix ash_envelope.gen.key_grants` shall reinforce this by scaffolding (a) a parent-resource `:read` policy section ("4b") with three labeled, commented-out time-bound patterns (trial / subscription / membership) and (b) an `is_nil(expires_at) or expires_at > now()` clause in the grants-resource `:read` policy as defense in depth against direct reads bypassing `resolve_for_actor/4`. | SG4, SG9 | T20 | Documentation, FDP_ACF |
| **SR28** | The library shall depend on `AshStorage.Layer.Encryption` rejecting `direct_upload/2` (returning `{:error, _}`) as a **load-bearing contract**. An automated test in this project shall exercise the encryption layer's `direct_upload/2` callback and assert it returns an error. If a future ash_storage revision relaxes the rejection, that test must fail. | SG1, SG2, SG6 | T22 | FCS_COP, FPT |
| **SR29** | When variants are configured on an encrypted attachment, the variant generation pipeline (`ash_storage`-owned) shall: (a) hold the unwrapped DEK in process memory only for the duration of the generate call; (b) write the decrypted source to a process-owned temp file; (c) remove the temp file in a `try/finally` `File.rm/1` on **all exit paths** including transform crashes. The ash_envelope project shall verify by a test that exercises a variant transform that crashes mid-run and asserts the temp file is absent afterward. | SG3 | T21 | FDP_RIP |
| **SR30** | The library shall document, in the getting-started tutorial and in the storage-services section of the topics docs, that **storage-service credentials (S3 keys, Azure SAS, disk HMAC signing secret) are an integrator-managed secret class equivalent to the env seal key.** Storage in source control, in build images alongside ciphertexts, in committed container `ENV` layers, in logs, or in error reports is excluded. | SG3, SG9 | T24 | Documentation |
| **SR31** | The library shall document, in the `expiring-grants` and storage-services topics and in the `KeyGrants` BlobIO manager moduledoc, that **the encrypted-blob HTTP serving path requires an integrator-controlled signed-token bearer with sensible expiry and rotation.** The encryption layer already forces `proxy_url` and emits `access: {:signed, secret: …}`, but the proxy *route's* authentication middleware, token-expiry policy, and key-rotation cadence are the integrator's responsibility. | SG1, SG4, SG7 | T9 | Documentation, FDP_ACC |
| **SR32** | The library shall require an `ash_storage` version that supports `AshStorage.Plug.Proxy`'s `:actor_assign` and `:max_lifetime_seconds` options, and shall document, in the `how-envelope-encryption-works` topic and the `KeyGrants` BlobIO manager moduledoc, the canonical wiring for encrypted-blob serving: (a) `forward "<base>", AshStorage.Plug.Proxy, resource: …, attachment: …, access: {:signed, secret: …}, actor_assign: <conn assigns key>, max_lifetime_seconds: 300` inside an authenticated router scope; (b) the outer-auth pipeline (`require_authenticated_user`, `Guardian.Plug.EnsureAuthenticated`, etc.) runs *before* the proxy `forward` so `conn.assigns[<key>]` is populated when the proxy resolves it — the bearer alone is not authentication; (c) the `:max_lifetime_seconds` cap is enforced server-side regardless of the URL builder's `:expires_in`; (d) signing-secret rotation cadence (≥ annually) and the proxy's two-phase rotation procedure. Documentation shall be explicit that `:actor_assign` is load-bearing for the `KeyGrants` manager — without it, `bctx.actor` is `nil` and the manager's policy check has no principal to authorize against. | SG1, SG4, SG7 | T9 | FDP_ACC, FDP_ACF, FMT, Documentation |
| **SR34** | The library's Spark DSL transformers and verifiers (currently `AshEnvelope.Reconcile.Transformers.ValidateConfig` and `AshEnvelope.Reconcile.Affecting.Transformers.InjectSyncPrincipal`) shall be covered by automated tests exercising both happy and sad paths: a valid configuration compiles cleanly, and known-bad configurations (missing required fields, mismatched attribute names between encrypted and grants resources, type mismatches) produce a `Spark.Error.DslError` at compile time rather than silently accepting the malformed state. New transformers / verifiers added to the library shall ship with equivalent coverage. | SG4, SG5, SG6 | T25 | FDP_ACC, FPT |
| **SR35** | Library-provided Mix tasks under `Mix.Tasks.AshEnvelope.Gen.*` shall emit guidance via `Igniter.add_notice/2` only and shall never write integrator files directly. Module-name arguments shall be parsed via `Igniter.Project.Module.parse/1`; arbitrary user-supplied strings shall never reach `File.write/2`, `File.cp/2`, or shell execution. Tasks that legitimately read integrator-supplied paths (`mix ash_envelope.rotate_backup_key --previous-private-key-path …`) document the trust assumption and treat the supplied path as untrusted-only-to-the-process-owner (i.e. EA1 holds). | SG3, SG9 | T26 | FPT, FDP_ACC |
| **SR33** | The library shall document, in the `how-envelope-encryption-works` topic, the security-relevant semantics of `AshStorage.Service.Mirror`: (a) writes fan out sequentially and partial failures on secondaries do not roll back earlier successes; (b) AEAD on the ciphertext guarantees that a read falling through to a divergent secondary fails closed with `:decryption_failed` rather than returning wrong-blob plaintext; (c) orphans left on secondaries are an availability / storage-cost concern, not a confidentiality one; (d) the recommended interim mitigation (monitor `Logger.warning/1` output and run a key-list reconciliation cron) until `ash_storage` ships structured orphan-cleanup tooling. Documentation shall be cross-referenced from `T23` in the risk-assessment matrix. | SG2, SG8, SG9 | T23 | Documentation, FDP_SDI |

> SR1, SR11, SR12, SR18, and the older "per-mode" framing of SR2 covered code paths that no longer exist in v0.3.0 (`:simple` storage mode, `AshEnvelope.Storage.Plug`, the process-dictionary DEK handoff). They have been retired with the code; T1 and T9 are removed from the risk matrix in step 4.

## Environmental Assumptions (EAs)

Security needs that are **not** met by the library itself but by its environment (the integrating application, its infrastructure, or its operators).

| ID | Assumption | Goal(s) | Threat(s) | Owner |
|---|---|---|---|---|
| **EA1** | The integrator authenticates the `actor` map before passing it to any AshEnvelope API; `actor.id` is bound to a real authenticated principal. | SG4, SG7 | T10, MC15 | Integrator |
| **EA2** | The integrator stores principal X25519 private keys at a protection level at least equal to that of the encrypted plaintext. Storage in the same row as wrapped DEKs in plaintext form is explicitly excluded. (Acceptable patterns: KMS/HSM-backed KEK encryption, Cloak-style application-layer encryption with a master key outside the DB.) | SG3, SG7 | T3 | Integrator |
| **EA3** | The integrator defines Ash policies on the `KeyGrants`, `GrantRequests`, and encrypted resources that correctly enforce "who may read / share / revoke / request." The library's defaults (`authorize?: true`) route through these policies. | SG4 | T10, T11 | Integrator |
| **EA4** | Transport between client and BEAM node uses TLS. Transport between BEAM node and database / object storage uses TLS where applicable. | SG1 | MC1 | Integrator / operator |
| **EA5** | Host OS and BEAM node integrity are not in scope: no rogue NIF, no side-channel attacker, no `Process.info` adversary, no memory dump. | SG3 | T11 | Operator |
| **EA6** | The Oban queue persistence used by `:async` reconciliation mode runs against a database whose access controls are at least as strong as the integrator's main DB. The job args contain only ids and are not in themselves secret (verified by SR9). | SG3 | T7 | Integrator / operator |
| **EA8** | Cryptographic algorithms used by the library (AES-256-GCM, X25519, HKDF-SHA256) remain acceptable per BSI TR-02102 horizon 2030. Quantum-capable adversaries are out of scope until that horizon is revised; the library's review cadence (SR17) tracks the horizon. | SG9 | T14 | Maintainer / cryptographic-policy stakeholder |
| **EA9** | When the integrator opts into backup-key escrow by setting `:backup_public_key`, the matching private key is stored at a protection level at least equal to the encrypted plaintext, outside the application database, and is only brought online for recovery or rotation. Acceptable patterns: cold storage, KMS / HSM-protected unwrap, split-key custody (Shamir / threshold). Storage in a column or environment variable accessible to ordinary application processes is excluded. | SG3, SG7 | T15 | Integrator |
| **EA10** | When the integrator opts into expiring-grants (`:expires_at_attribute` set on `KeyGrants.Config`), the env seal key (A10) is sourced from an operator-managed secret (env var, secrets store, KMS bootstrap) and treated as application-level secret material. Storage in source control, in build images alongside ciphertexts, in logs, or in error reports is excluded. Rotation is via "drain via TTL" — set new key, wait for the maximum configured TTL, retire old key. Weaker than EA9 by design (seal key is reached by every analyzer run; can't realistically live in cold storage); TTL is the compensating control. | SG1, SG3, SG7 | T17, T18 | Integrator / operator |
| **EA11** | Storage-service credentials (A11) — AWS access keys, Azure SAS, disk HMAC signing secret — are sourced from operator-managed config or IAM (cloud IAM with instance roles, secrets store, KMS-unwrapped env). Storage in source control, in build images alongside ciphertexts, in committed container `ENV` layers, in logs, or in error reports is excluded. Credential rotation is the integrator's responsibility; ash_envelope provides no rotation tooling for storage-service credentials. Bucket / blob-store IAM should grant the BEAM node only the permissions required by the configured services (no broad `*:*`). | SG1, SG3 | T24, T4 (when credentials are writable) | Integrator / operator |

> EA7 (no `:simple` mode against DBA-class threats) is retired alongside the `:simple` code path. The configuration cliff it guarded against no longer exists.
